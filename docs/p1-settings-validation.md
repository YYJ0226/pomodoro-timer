# P1：设置输入校验与真实回归

日期：2026-10-17。范围：原有 Windows Tkinter 应用的时长设置，未重写 UI 或实现后续统计功能。

需求：[Issue #1](https://github.com/YYJ0226/pomodoro-timer/issues/1)。基线：`4edfb9ae0998c8ef742407efffa5c06b3e032557`。

## 问题与修复

Spinbox 的上下箭头范围不能阻止手动输入。原实现先写入工作时长，再解析休息时长：

- 工作输入 `0`，刷新进度条时出现 `ZeroDivisionError`。
- 工作输入 `30`、休息输入 `oops`，虽然报错，但工作时长已从 1500 秒变成 1800 秒。
- 零、负数和越界值没有完整拒绝。

修复使用无副作用的 `parse_duration`，两项校验都成功才更新设置。工作范围 1–60 分钟，休息范围 1–30 分钟；只接受去掉首尾空格后的半角十进制数字，允许前导零。错误信息包含具体字段及范围。

无效输入不重置计时、不改变模式、剩余秒数或完成数；合法输入沿用原行为，停止并重置当前模式。这里的“一起应用”指验证失败不发生部分写入，并不是对既有线程模型作并发事务保证。

## 桌面验收清单（待人工完成）

- 运行 `python pomodoro.py`，工作填 `0`、休息填 `5`，应用后出现工作范围提示且不崩溃。
- 工作填 `30`、休息填 `oops`，提示休息输入有误；原工作时长和当前计时不变。
- 工作填 `30`、休息填 `10`，提示成功，工作模式显示 `30:00`；切到休息显示 `10:00`。
- 在休息模式运行时应用错误输入，计时不被重置；输入修正后仍可应用。
- 工作 60、休息 30 可应用；工作 61、休息 31 分别被拒绝。

无界面测试不是完整 GUI 运行证明。当前自动化环境不能采集原生 Tk 窗口，以上仍需本人验收；视频若使用界面截图或录屏，必须来自真实桌面，不用手绘画面冒充。
